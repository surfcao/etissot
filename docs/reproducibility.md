# Reproduce the manuscript results

Software review snapshot: 15 October 2026. The author requested manuscript review without edits; the working manuscript sources, figures and PDFs are unchanged. The package now includes the newer checkpoint audits, neighborhood controls and revised-figure generators. Fifteen distinct figures, 21 live tables, 20 marked blocks and 124 numerical checks are covered across the combined manuscript and package-only additional results. The manually typeset CSP table is checked in full against an independently regenerated table.

## Clean reproduction

```sh
python -m pip install -r requirements-reproduce.txt
python -m pip install .
python -m unittest discover -s tests -v
etissot reproduce --data data --output reproduced --manuscript manuscript --numerical-only
```

Use a new output directory. The workflow regenerates outputs from declared inputs; it does not prefill finished tables, summaries or figures. `run_report.json`, per-step logs, `environment.json` and `manuscript_verification.json` record the outcome. The numerical-only option still checks every generated block, the complete CSP table, numerical macros, numerical claims and the presence of all figures. It explicitly reports pixel differences; it is not an exact-artifact check. Without the option, pixel identity remains mandatory.

The study environment uses Matplotlib 3.11.0 for historical package figures. Eight newer manuscript figures were originally rendered with 3.10.9. An isolated renderer avoids changing the primary environment:

```sh
python -m pip install --no-deps --target .figure-renderer -r requirements-figures.txt
export ETISSOT_FIGURE_LIBRARIES="$PWD/.figure-renderer"
etissot reproduce --data data --output reproduced --manuscript manuscript --numerical-only
```

The figure worker records its versions in `summaries/figure_environment.json` and writes only to the output directory. Matching a renderer version does not guarantee identical pixels across platforms. In the local review, three of the eight new figures matched exactly under 3.10.9; five retained small rasterization differences. Exact pixel verification is therefore not reported as passed for the current manuscript. The original figure files were preserved.

## Inputs and regeneration scope

- Global, randomized, dense and multiradius profiles, cached Jacobians, candidate distances and saved GP parameters remain the scientific inputs described below.
- `data/profiles/common_radius_0p3.npz` contains 32-bearing profiles for all thirteen checkpoints at the common radius. `checkpoint-audits` refits them and recomputes the common-radius column.
- `data/measurements/review/csp_precision.json` contains the CSP site-level feature-fit and Jacobian measurements. Precision-error quantiles and every displayed table entry are recomputed from these rows. Fresh Jacobian evaluation is a separate checkpoint-dependent operation.
- `data/measurements/review/review_followups.json` is a declared record of checkpoint evaluation audits, including activation crossings and bearing-count sensitivities. These retained aggregate measurements are formatted into tables; the package does not claim that hidden activations or the original 64-bearing model evaluations are reacquired by cached reproduction.
- `neighborhood-controls` recomputes null rankings, larger-neighborhood comparisons and the query-cluster bootstrap from `data/measurements/neighbourhoods.npz`, with fixed seeds.
- `manuscript-figures` regenerates the current schematic, profiles, geographic references, global/regional fields and neighborhood maps. Historical package figures remain generated by their original reporting modules.
- The full workflow replays 360 selected GP objectives and predictions and all downstream bootstrap calculations. It does not retrain models or reacquire original source datasets.

Fresh model-dependent review commands are retained under `scripts/review_followups.py` and `scripts/csp_precision_check.py`. They require the pinned external model files and CSP runtime sources. Their checkpoint evaluations were not rerun during this software review. `scripts/neighbourhood_nulls.py` and `scripts/make_revision_figures.py` retain the original local research entry points; the reusable, workspace-based implementations are in `etissot.diagnostics.neighborhood_controls`, `etissot.reporting.checkpoint_audits` and `etissot.reporting.manuscript_figures`.
